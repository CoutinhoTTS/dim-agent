# Agent 上下文：目标与待定义的需求

状态：需求定义草案，不是设计。本文只写每一块要达到什么目的、能带来什么、要先回答哪些问题；需求定下来之后，再分别进入各自的设计文档。现有机制只给出入口链接，不在这里展开。

Dim 是一个编程 agent。它的上下文工作只有一个总目标：**模型在每一步看到的，正好是它把用户的事情做对所需要的东西，并且在长任务、多条工作线下依然如此。** 下面三块分别服务这个目标的不同侧面。

## 1. Timeline 分支

**目的。** 让一个 Session 能从同一段历史出发，同时推进不止一条工作线，而不打断或污染主线。

**能带来什么。**

- 用户：从某个历史点另起一支试别的做法，对比之后决定采用哪一支；主线不受影响。
- Agent：在不打乱主线上下文的情况下，把一件旁支工作（试一种方案、自查、评审）放到一条独立的线上做完。
- 插件：在同一 Session 内发起自己的工作线，例如 Pursuit 用评审分支判断目标是否完成。

**要先回答的问题。**

1. 分支解决的是谁的什么场景？上面三类里哪些是要支持的，优先级如何？
2. 什么时候该用分支，什么时候该用 Collaboration 成员（新的 Session）或 fork（新的 Session）？三者的边界要从用途上说清楚。
3. 一条分支做完之后，结果对谁有用、以什么形式回到需要它的地方，还是不回去？
4. 一条分支什么时候算结束？结束之后用户还要不要看到它？
5. 用户需要在界面上看到分支的哪些东西、能对它做什么（跟进、比较、采用、丢弃）？
6. 怎样算这件事做成了？

**现有基础。** [设计规则](../architecture/rust-agent/principles.md)（分支是平等、并行的行为线）、[TimelineTree](../architecture/rust-agent/plugins/TimelineTree.md)、[Pursuit](plugins/Pursuit.md)、[Session 删除与 fork](appserver/session-deletion-and-fork.md)、[客户端总体设计](https://github.com/arcships/dim/pull/424)（#424，未合并）。需求跟踪：[#427](https://github.com/arcships/dim/issues/427)。

## 2. 压缩

**目的。** 任务超过上下文窗口之后，agent 照样能接着把事情做完，用户感觉不到质量下降，也不用把前面说过的话再讲一遍。

**能带来什么。**

- 长任务不因为上下文满了而中断或跑偏。
- 用户的目标、约束和已经做出的决定在压缩之后依然有效。
- 被摘要省略的原话在需要时能找回来（[Recall](plugins/Recall.md)）。

**要先回答的问题。**

1. 压缩之后什么必须保住：目标、约束、已做的决定、当前步骤、改过的文件、用户偏好……哪些是必须的，哪些丢了可以接受（因为能用 Recall 找回）？
2. 用户需要知道压缩发生了吗？需要能手动触发或控制它吗？
3. 成本上的界限是什么：一次压缩的耗时和费用、长历史下每一轮的开销？
4. 怎样判断压缩“做得好”：用哪些任务、什么样的通过标准？[#170](https://github.com/arcships/dim/issues/170) 的摘要评估是其中一种手段，它要服务于这里定下的标准。

**现有基础。** [ContextCompaction](plugins/ContextCompaction.md)（机制已实现，效果未评估）、[压缩触发研究](research/compaction-trigger.md)、[Recall](plugins/Recall.md)（#310）。需求跟踪：[#428](https://github.com/arcships/dim/issues/428)。

## 3. 给模型的提示词

**目的。** 模型按产品期望的方式工作，并且理解运行时塞进上下文的每一样东西；产品行为能被有依据地调整。

**能带来什么。**

- 模型能分清哪些是用户说的、哪些是运行时补充的，并正确使用它们。
- 产品可以在有评估依据的前提下调整模型的行为，而不是凭感觉改字符串。
- 用户和项目能在合适的范围内定制模型的行为。

**要先回答的问题。**

1. 哪些文字是产品策略（应当可以调整，并且改动要有评估），哪些是和行为绑定的契约（跟着行为走，不单独调）？
2. 谁可以改什么：产品、用户、项目、插件各自能影响到哪一层？
3. 元提示（向模型解释运行时内容的那段说明）要覆盖什么，由谁保证它和运行时实际写入的内容一致？
4. 给模型的提示词用什么语言？“Agent 提示词语言”这个功能要解决什么问题？
5. 一次提示词改动怎样判断是变好还是变坏？

**现有基础。** [提示词](../architecture/rust-agent/prompt.md)（元提示为首版，效果待评测）、[PromptSources](../architecture/rust-agent/plugins/PromptSources.md)。需求跟踪：[#429](https://github.com/arcships/dim/issues/429)。
