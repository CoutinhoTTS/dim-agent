# Migration plugin

Migration 将当前旧版 CLI／Desktop 的已有数据转换成当前原生格式。它是按客户端入口临时加载的 process 插件，拥有来源解析、字段映射、目标写入、任务、进度、回执和重试。客户端负责入口、路径选择和展示；导入结束后卸载插件。首个入口为 CLI，Desktop 复用同一实现，自动触发策略由客户端另行设计。

迁移逻辑全部位于 Migration。其他业务模块、插件和 App Server 直接读取导入后的正常数据，不增加迁移 RPC、旧格式分支、专用上下文入口或导入回调，也不为迁移修改原生存储格式。

规则见[设计规则](../../architecture/rust-agent/principles.md)、[插件契约](../plugin-contract.md)、[rutis 用法](../rutis-usage.md)、[ADR 002](../../adr/002-plugin-scope.md)。交付与验证见[实施计划](../../plan/analysis/legacy-migration.md)，当前格式绑定见 [Migration README](../../../crates/dim-migration/README.md)。

## 输入、输出与生命周期

宿主提供产品 home、原生存储的相对目录和客户端支持的主题标识；请求提供已解析的旧 home、停止写入的确认，以及可选的重试任务。插件不猜测发行渠道或 Desktop 的 storage-root。CLI 的 Global／CN 路由与命令交互由[命令合同](../cli-commands.md#migration-interaction)定义。

- `inspect` 返回数据库清单、对象数和可诊断的来源问题。
- `run`、`retry` 返回任务及逐对象结果，运行时提供进度订阅。
- `list`、`show`、`cancel` 读取任务或请求停止，不依赖常驻插件或业务守护进程。
- 结果区分导入、已导入、已删除、冲突、暂缓、不支持和失败；列出被保留的未映射字段。进度和报告不包含凭据或会话正文。

来源必须停止写入。运行导入时目标客户端也须退出，宿主通过普通关闭流程结算目标守护进程；插件取得原生库的排他访问权后才转换目标数据。插件不杀旧进程、不启动旧插件。取消停止接收新对象，已接受的原子提交先结算；卸载等待任务、资源释放和结果落盘。

## 来源边界

来源限定旧仓库 `389f80731effbcd7694541eda934fd5dc2f39c9f` 的 CLI／Desktop 数据。源码路径不是数据 home。主要依据是旧仓库的 `packages/agent/src/types/storage.ts`、SQLite 存储、OAuth store、Provider 及内置插件持久化实现。

插件复制源数据库及已提交 WAL 到私有快照，只通过 SQLite 打开快照，不创建源 SHM 或改写来源。JSON、附件、产物从授权来源根读取，拒绝符号链接和越界路径。快照在操作结算时删除。开发验证只使用一次性旧库与隔离目标。

## 数据映射

| 来源 | Migration 的转换与目标行为 |
| --- | --- |
| `providers`、`provider_selections` | 转换静态连接、凭据、模型来源、覆盖、偏好、启用状态和作用域选择。保留已配置目标；兼容部分可导入，其他字段逐项报告并保留来源 |
| OAuth `auth.json` | 导入兼容的 Dim、Codex、Grok 登录记录，验证结构、版本及已有账号状态摘要。保留目标账号和其他所有者字段；凭据继续遵守正常客户端的有效期与恢复逻辑 |
| `mcp.json`、MCP OAuth | 转换受支持的服务设置；OAuth 与目标服务 URL、资源、客户端注册和作用域绑定，保留已有凭据；不从历史工具结果推导登录或授权 |
| CLI 与 Desktop 设置 | 有等价语义的共享项先选旧 Desktop 值，再与目标比较。只补未配置项；`false`、空值与显式清除均保留 |
| Skills、Web、exec shell | 保留兼容设置及启用／禁用状态。共享 Skills 来源复用路径；不明确的 ID、未支持的 Web adapter 与设置保留来源，不选择替代实现 |
| 长期命令权限 | 仅转换等价的 allow／deny 规则；原规则优先级无法表达时保留相关组，不近似放宽权限。单次审批保持历史资料 |
| `sessions`、`session_states`、`messages`、`compaction_states` | 创建完整的原生会话、历史、模型引用和有效上下文；身份、可见性与回执原子发布。当前 Provider／模型不可用不阻止历史导入 |
| 附件与 Session blobs | 校验内容、复制为会话拥有的不可变文件、重映射引用；历史档案保留附件、blob 元数据和新路径，删除和 fork 遵循正常会话文件规则 |
| 队列、后台任务、Workflow 运行、调度执行、权限与用量记录 | 保留历史结果和可用产物，链接为可读的会话档案；不恢复运行、队列投递、PID、审批或新版用量测量 |
| 调度配置 | 转换有精确日历等价的 RRULE、模式、模型与已导入的绑定会话，保留启用／禁用状态；不恢复旧执行记录。不能等价表达的规则保留来源 |
| 已归档会话 | 当前客户端没有归档能力时整条暂缓，不显示为普通会话 |
| 加密远端压缩会话 | 当前格式不能保留其续聊状态时整条暂缓，保留旧库；不改用全部原文或占位摘要，也不修改其他模块增加专用受阻状态 |
| 未实现功能、未知插件私有状态与文件回退 | 保留旧数据并报告，功能具备后差量导入；不为迁移补建业务功能 |

设置、账号、调度和 Provider 的来源不兼容不能覆盖合法目标，也不能影响独立对象。来源损坏、目标不可写等公共故障使任务失败。错误结果保留源数据和已完成对象。

## Session 的历史与续聊状态

旧消息没有当前 Timeline，Migration 记录一次明确的导入操作，并将保存的消息内容转换为现有原生历史记录。来源标记、原消息 ID 和来源时间可追溯。导入不产生历史模型请求、工具派发、审批决定或用量测量，也不执行旧工具。

完整历史与模型有效上下文分别保存。界面通过正常历史投影逐条查看旧消息；模型使用旧版有效摘要及未压缩后缀，保留 `user`、`assistant`、`tool_result` 角色与工具配对。回退边界、私有输入、重试展示和压缩边界在来源解析时确定，不能让展示需要扩大续聊上下文。

有效上下文通过既有持久化上下文替换记录保存，并包含说明来源的最终内容。此转换是导入时的确定性操作，不请求模型重新压缩。历史内容、保留上下文和来源标记一起提交，重开后普通上下文逻辑直接读取。

```text
Imported legacy Session
  User       original message          [source time]
  Assistant  original reply            [source time]
  Tool       historical result         [source time]
  Import     source + metadata archive [import time]
             effective summary + suffix retained

  User       new request               [native time]
  Assistant  normal continuation       [native time]
```

原生上下文不能表达的材料不会作为文本摘要写入。加密远端压缩和不完整角色／工具配对整条暂缓，直到存在兼容转换；暂缓项没有导入完成回执。

## 原生格式与提交

Migration 自己维护当前原生持久化格式的转换适配，不把旧 schema 交给业务所有者。它复用正常存储初始化和格式校验，持有与正常守护进程相同的排他租约，关闭数据库后释放租约。格式不兼容时保留目标并失败，不降低版本、删库或改造消费者。

会话文件先在不可见的会话发布之前写入；历史、目录、归属、文件所有权和导入回执在同一原生事务提交。失败时不发布半个会话，清理本次未被会话拥有的文件。其他原生文档与对应回执在同一事务保存；需要文件替换的设置保留写入意图，不能确认的中断结果作为冲突保留，避免恢复用户已清除的值。

回执是 Migration 的私有持久化数据，使用现有通用文档存储，不增加表或格式版本。删除普通会话、Provider 或调度不删除回执。已导入身份的已删除目标不会因重试而复活；已覆盖字段改变时保留目标；尚未支持的字段和暂缓对象没有完成标记，后续可以补导。

## 任务与恢复

任务在产品 home 的 Migration 私有目录保存状态与逐对象结果。运行租约区分正在运行与进程中断；无租约的未结算任务报告为中断。重试生成关联旧任务的新任务，重新读取来源并核对原生回执，不只依赖上一次终端报告。

任务目录创建后尚未写入状态与结果的中断可以忽略；已有结果但缺失任务状态是完整性错误，不能伪装成空任务。一次只接受一个目标库的写入者；两个发行渠道的任务相互独立。取消与插件卸载等待已接受工作结算，不回滚已完成对象。

## Requirements raised to mechanism owners

没有首版实施所需的新机制要求。原生格式、普通历史和上下文消费者保持现有合同；无法表达的远端压缩会话与未实现功能按上文整条暂缓。未来要支持这些材料，应另行提出通用能力，不将 Migration 专属判断加入核心。

## Rule check

Migration 是普通 process 插件，拥有一次导入的任务、存储适配、排他访问和生命周期；不挂载 Session／branch Capability，不参与活动分支的事件消费。

| 规则 | 适用方式 |
| --- | --- |
| §4.1 状态所有权 | 停机后在持久化边界转换数据，不调用活动业务插件或写其运行内存；恢复运行后由正常所有者读取 |
| §4.2 交接 | 原生事务提交是发布点，取消不撤回已提交对象 |
| §4.3 before | 不注册 before |
| §4.4 核心无业务 | 来源识别、映射、回执全部在 Migration，消费者没有旧格式分支 |
| §4.5 原子批次 | 历史消息的相关记录保留批次边界，完整会话和回执原子提交 |
| §4.6 上下文 | 保存明确来源的已有消息内容和有效上下文，不使用扩展事件直接投影正文 |
| §4.7 公开交互 | 宿主通过插件服务调用；格式转换只读取显式授权、停止写入的持久化数据，不读取业务插件内部服务 |
| §4.8 基础设施 | 不改基础机制，无首版新增要求 |
| §4.9 必要事实 | 导入标记和保留内容是持久化历史，任务进度留在 process 私有目录 |
| §1 Capability | 无 Session／branch 事件处理部件，不新增 Capability |
| ADR 002 D1 | 跨会话导入属于 process，实例只活到结算与卸载 |
| ADR 002 D2 | 不增加接线插件、导入注册表或平行事件总线 |
| ADR 002 D3 | 正常聊天不依赖 Migration；格式适配依赖现有类型与正常存储初始化 |
| ADR 002 D4 | 来源与重试是请求数据；触发策略由客户端决定 |
| ADR 002 D5 | CLI／Desktop 复用共享数据服务和结果，Rust 绑定留在 crate README |

## 消融检查

保留一个插件、一个任务账本和一个版本明确的原生格式适配。去掉跨业务导入 RPC、接收插件回调、专用上下文类型和原生格式扩展。排他租约用于阻止并发写入，原子回执用于重试与删除语义，来源快照用于保护旧库；这些结构分别保护实际数据边界。
