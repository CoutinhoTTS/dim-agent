# Migration 实施计划

目标与映射依据：[Migration plugin](../../design/plugins/Migration.md)。交付范围是独立的 Migration 插件和 CLI 手动入口；Desktop 复用接口，后续自行接线。实现只改 Migration、必要的 CLI／构建接入和相应文档、验证，不向其他业务插件或 App Server 增加导入逻辑。

## 交付单元

| 单元 | 内容 | 验收证据 |
| --- | --- | --- |
| 来源边界 | 当前旧 CLI／Desktop 的 SQLite schema、已提交 WAL、JSON、附件与产物；快照与来源根约束 | 一次性数据库覆盖 WAL、损坏 schema、越界和符号链接；读取前后来源字节不变 |
| 原生适配 | Migration 内部转换当前原生格式，复用正常初始化与格式校验，取得同一排他租约 | 未改动的原生存储冷开成功；活动目标拒绝并发写；不兼容目标完整保留 |
| Session | 完整角色历史、来源标记、时间、附件、摘要／后缀与回退解释；历史、归属、文件所有权和回执原子发布 | 普通历史查看／导出、新输入和捕获的模型请求；导入没有模型请求或工具派发；无半个会话 |
| 配置数据 | Provider、兼容账号、MCP、Skills、Web、客户端偏好、命令规则和调度 | 正常消费者读取；目标值与启用状态保留；凭据不进入报告；不支持字段可追踪 |
| 任务 | 账本、进度、逐对象结果、租约、取消、重试、卸载和重新加载 | 取消先结算；中断可重试；已有对象去重；用户删除／清除不会复活 |
| CLI | `migration` 默认导入，及 inspect／run／list／show／retry／cancel；Global／CN 各自导入；终端面板归 Migration | 真实 CLI 对隔离用户 home 跑通两渠道、历史导出、重试和查询；宽窄屏、Ctrl+C 和结束摘要，JSON 输出保持完整 |
| 文档与边界 | 共享宿主接口、原生格式绑定、CLI ASCII 流程和实施说明 | PR 相对 main 的业务源码仅含 Migration 与必要 CLI 接线；无其他业务插件、App Server 或原生格式改动 |

## 实施顺序

1. 使用隔离旧库核对来源 schema、压缩、回退、附件与配置。客户端解析发行路径，核心只接收明确的来源、产品 home 和正常原生存储位置。
2. 建立插件内部的原生格式适配，先证明未改动消费者能冷开一条导入会话并沿用有效上下文。保持原生格式及公开协议不变。
3. 把 Provider、设置、账号、权限与调度的兼容转换、字段覆盖回执和文件替换写入收进同一插件。目标已配置值优先，旧客户端共享项以 Desktop 为准。
4. 接上持久化任务与 CLI：停止写入确认、进度、逐对象结果、取消和关联重试。查询不启动目标进程；导入通过普通流程关闭目标进程后再取得排他访问权。
5. 以普通消费者验证每种目标数据，覆盖来源不变、失败隔离、已删除对象、已清除偏好、取消／卸载、目标格式与大小边界。
6. 检查并删除不服务交付的中间层。生成实际依赖图，执行边界和文档检查，再运行与最终改动相称的格式、Clippy、测试和脚本检查。完成后更新 PR 并转为 Ready for review。

## 重要边界

- 兼容性检查与导入转换在 Migration 内，业务所有者只处理正常原生数据。初始化、原生类型与纯校验可以复用，不新增导入专用 API。
- 完整展示历史与模型有效上下文分开保存。模型保留原生角色、配对、有效摘要和未压缩后缀；不重新采用已回退／私有／重试展示内容，不自动请求模型重新压缩。
- 加密远端压缩会话整条暂缓，保留旧库，不能用占位摘要或全部原文替代。暂缓身份不封死后续补导。
- 原模型／Provider 不可用本身不阻止普通会话历史导入，打开时沿用客户端正常处理。
- 已归档会话、未实现业务与未知私有状态保留来源；可读的历史结果不会变成运行、审批、用量测量或待执行队列。
- 所有开发与验证使用一次性 home；不拿用户产品库试验，不降级或删除不兼容原生库。
- 一次对象提交必须能与回执核对。跨文件写入无法确认的中断保留为冲突，不冒险重放并覆盖用户后续操作。

## 验证矩阵

| 用户行为／故障 | 预期结果 |
| --- | --- |
| 同时存在 Global／CN 旧目录 | 两条独立任务与结果，各自原生目录保存，不合并 Session、Provider 或设置 |
| 旧库有已提交 WAL | 快照读到提交，源主库、WAL、SHM 保持不变 |
| 完整历史包含压缩、回退、重试展示、工具和附件 | 可读历史保留；模型仅采用有效上下文和原生角色；旧工具零派发 |
| 目标模型已删除 | 历史导入成功，普通客户端处理缺失模型 |
| 远端压缩材料不兼容 | 整条会话暂缓，来源保留，无错误续聊上下文 |
| 目标已有 false／null／空值或用户清除偏好 | 目标保持原值／清除状态，报告冲突或已删除，不回填 |
| Provider 含部分不兼容配置 | 兼容部分导入，未支持字段列出并保留，回执只覆盖已理解字段 |
| 兼容 OAuth 账号 | 正常账号消费者可读，已有账号不覆盖，不输出 token 或凭据 |
| 调度和 Web 原来禁用 | 导入仍禁用；普通功能加载处理配置，不恢复旧执行 |
| 单个对象损坏 | 记录原因，其他独立对象继续 |
| 图片内联后会使消息或有效上下文超限 | 保留完整会话文件、可读路径和省略报告；能放入预算的图片仍内联，不拒绝可导入的正文 |
| 交互终端导入 | 固定区域显示当前步骤、进度与最多 8 条结果；窄屏缩减，结束只留摘要与报告命令 |
| 管道或 `--json` | 完整 JSON 保持可解析，无终端控制序列；进度不逐对象刷屏 |
| 拒绝双渠道重试确认 | 退出 130，无新任务，无找不到任务的误报 |
| 用户删掉已导入会话／配置 | 重试不复活 |
| 取消、进程中断、插件卸载与重新加载 | 已接受工作结算，回执与账本可恢复，半个会话不可见 |
| 活动目标或不兼容格式 | 失败并保留已有目标；不自动降级、清空或修改消费者 |
| 过大或不可访问的内容 | 发布前明确拒绝，不截断后报成功 |

验证重用实际消费者与跨 crate／CLI 流程，只对无法稳定在用户流程触发的数据迁移故障保留独立测试。依赖与装配检查执行 `xtask graph/check`；脚本变化执行 Node 测试；合并前按仓库规则完成工作区检查。无需为迁移修改冻结事件格式基线。
