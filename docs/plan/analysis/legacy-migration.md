# Migration 实施计划

目标与映射依据：[Migration plugin 提议](../../design/plugins/Migration.md)。本计划提出模块边界、依赖、交付单元和验证要求，不改变其他所有者的现有合同。跨模块接口确认后才能实施；交付状态由后续 issues 跟踪。

## 1. 设计收敛

先完成以下决定，再建立可实现的任务：

1. 核对调研 §3 的数据清单和目标业务功能的实际实现状态：业务功能尚未实现的数据暂不导入，保留旧版来源并记录暂缓项，后续差量补导；不为迁移补建这些业务功能。继续明确已实现功能的字段映射与设置生效语义。目标已有配置时保留目标值，只补未配置项并报告冲突；旧 CLI/Desktop 的共享设置冲突且目标未配置时，以旧 Desktop 为准。Provider 已确定导入兼容部分、明确报告未迁移设置并保留来源，须由 Provider 所有者更新现有整条拒绝的合同。模型失效不阻止历史导入，使用普通客户端的打开、续聊逻辑，不增加迁移专属状态或恢复流程。
2. 落实原生角色历史的通用采用合同，按已确认的“保留旧版续聊状态”保留有效摘要与未压缩后缀，并排除已回退内容。核对远端压缩材料兼容性，确定不完整工具配对与不兼容材料的受阻结果；不自动改用全部原文。
3. 确认 Session 创建幂等、分块导入、附件、完成发布及删除后重试的合同；保留模型引用，不以当前模型可用性作为导入创建门槛。
4. 落实按需加载、执行、结果持久化、收尾卸载的共享插件生命周期；核对宿主临时装载入口，不使用持久化 `plugin.enable/disable` 模拟临时调用。确认装载期间的共享管理接口、任务持久化格式、取消/重启语义，以及协议和原生存储的显式兼容决定。
   首版入口明确要求先退出使用同一旧 home 的旧 CLI／Desktop，来源停止写入后再迁移；来源读取与诊断遵守该边界，不主动终止旧进程。
5. 在各所有者的设计文档中落下所需合同，建立对应 issues。Migration 只定义自己拥有的合同，不抄写其他所有者的实现；Provider 部分导入与差量账本、账户恢复等变化分别由所有者完成格式和接口决定。

## 2. 交付单元与依赖

| 单元 | 输入、输出与边界 | 涉及位置 | 验收 |
| --- | --- | --- | --- |
| M1：通用消息采用与历史读取 | 最终既有消息 → 采用输入、角色正确的模型上下文、逐条可读的公开历史 | `dim-agent-types`、输入/Loop/历史投影、相应协议/存储所有者；按合同更新类型导出 | 历史导入不发起模型调用或重放历史工具；下一次正常输入的模型请求角色和工具配对正确；重载、分块、压缩与 fork 不丢失或重复；兼容边界明确 |
| M2：可恢复的 Session 导入提交 | 稳定来源映射、元数据、历史、文件 → 一个完整可见的目标 Session | Agents、Sessions、SessionStore 与文件所有者；优先复用 prepared creation | 创建回复丢失、文件成功后中断、历史提交后账本未写等情况下重试不产生重复或半成品；删除后不复活；模型不可用仍能导入历史，客户端沿用普通逻辑；归档行为符合决定 |
| M3：Migration 插件 | 显式来源与任务请求 → 来源校验、实体转换、所有者调用、持久化结果及进度 | 独立 Migration crate；复用 Provider 导入；宿主只负责按需装载、方法接入与卸载 | 当前旧 CLI/Desktop schema fixture 均可读取；同源共享 home 不重复；源文件不变；冲突和不支持字段有逐项结果；结果保存和工作结算后可卸载，再次装载能读取进度并恢复 |
| M4：CLI 手动入口与逐条历史展示 | 命令触发按需装载 → 调用插件 → 结果保存与卸载 → 命令退出；公开历史 → CLI 消息与导出 | `dim-cli` 参数、client/wire、projection、导出、帮助和文档；宿主临时装载入口 | 隔离 home 中命令完成迁移并可重试；不改长期启用选择、不留下常驻迁移插件；进度与最终状态一致；历史逐条显示、导出保留角色，下一次用户请求正常续聊 |
| M5：Desktop 接入 | 导入入口按需加载同一插件，完成后卸载并展示结果；使用同一管理与历史合同 | Desktop 所属仓库 | 独立客户端设计之后安排；不属于首版 CLI 交付；不复制转换和恢复实现；卸载插件不退出 Desktop |

依赖顺序：设计收敛 → M1/M2 的所有者合同与实现 → M3 → M4。M1/M2 有重叠的历史和存储路径，不因拆为两行就要求并行开发。首版完成条件是 M1–M4 的完整用户流程；只提供 Provider 导入不能算完成 Session 迁移。

## 3. 必须接通的关系

1. CLI 命令通过宿主按需加载 Migration，再调用本次装载的插件接口；宿主持有装载生命周期，方法执行与进度状态由插件拥有，结果持久化和工作结算后卸载插件、退出命令。
2. Migration 的边界读取器识别当前旧 CLI/Desktop 实际 schema，从一致快照解码为明确类型，不启动旧客户端或旧插件。
3. Migration 调用 Provider 的导入，复用其字段映射和去重结果，并落实已确定的部分导入要求；OAuth 登录态通过 Dim 账户、模型账户和 MCP OAuth 各所有者的兼容导入与恢复操作处理，不塞入静态 Provider 导入。
4. Migration 通过 Sessions/SessionStore 所有者完成身份、元数据、文件和历史的可恢复提交。
5. 历史输入经过采用/消费进入模型上下文；公开历史读取、CLI 投影和导出解释同一个合同。
6. CLI 的断线或取消请求落到任务所有者；查询最终结果不依赖进度通知是否收到。
7. 插件再次按需装载或进程重启后，从持久化任务与目标回执核对实际结果，而不是从显示计数推断；查询和重试不依赖任务完成后插件仍常驻。

## 4. 验证范围

只使用一次性旧库 fixture、受管附件目录和隔离目标 `--home`；不打开用户的现有 store。旧 schema fixture 固定本次来源基线，不修改冻结的事件兼容 fixtures。

- 正常路径：纯文本、图片、工具调用/结果、标题、模型引用、关系、附件 bytes；按 `orderKey, messageId` 验证顺序，不按时间排序。Provider 含不支持设置时，兼容部分按合同导入、未迁移字段明确报告、来源保留；必要字段无效不能作为部分成功掩盖。
- 来源前置条件：CLI 命令及后续 Desktop 入口明确要求先退出旧版，迁移期间来源保持停止写入；只读快照包含 WAL 已提交内容，数据库及外部附件、配置保持一致，不调用旧存储初始化、不终止旧进程、不改写来源。
- 历史边界：逐条可读历史保留旧库仍保存的原消息；捕获首次续聊请求，确认旧摘要与未压缩后缀被采用、角色和配对不变、已回退内容不再生效。远端压缩材料按已验证兼容性处理，不兼容时不自动重新采用原文或调用模型。孤立工具结果、缺失附件、归档和 tags 按已确认范围处理。复用普通会话的模型失效用户流程，确认导入历史成功、模型引用保留，打开和续聊不增加迁移专属分支。
- 归档边界：目标客户端不支持归档时，整个已归档 Session 及其历史、附件不进入目标、不写已导入标记，旧版数据保留；目标功能具备后再差量导入并保留归档状态，不能先作为普通会话发布。
- 恢复路径：创建、文件、历史、完成发布与账本更新边界的故障注入；取消、重启、同源重复、来源移动、来源变化、目标冲突和用户删除后重试。
- 错误隔离：单个对象数据或转换失败时记录原因，其他独立对象继续完成，最终报告失败项；重试不重复已经完成的结果。来源整体不可读或目标库不可写等整体故障停止本次迁移，不逐对象重复失败，不回滚已完成对象。
- 按需生命周期：CLI 命令装载插件，执行期间显示进度，结算并保存结果后卸载、命令退出；长期插件启用配置不变。再次调用可读取上次结果和恢复进度，无需常驻 Migration；Desktop 后续接入同一生命周期并保持应用运行。
- 差量补导：目标业务功能缺失时，其数据不进入目标、不记为已导入，旧版来源保留；功能具备后再次执行迁移，只补导暂缓部分，复用身份映射，不重复或覆盖已迁内容。Provider 部分导入的未迁移设置同样可以在支持后补导，不能被整条已导入标记永久跳过。
- 设置冲突：先解析本次范围内的旧 CLI/Desktop 共享设置冲突，采用 Desktop 值，再与目标比较，不受文件遍历顺序影响。目标已配置值保持不变，只填未配置项并标明来源，冲突有明细；显式关闭、空列表及清除不能被旧设置覆盖。
- MCP 配置：用户级条目的原启用／禁用状态按冲突规则保留，由新版 MCP 的现有配置应用流程生效；不因迁移全部禁用，也不增加专门的启动流程。项目配置继续按既有来源与启用合同处理。
- 已实现功能的配置：统一保留原启用／禁用状态，复用各功能的正常应用与执行流程；已启用任务的正常触发不误判为历史重放，旧运行记录不恢复成正在执行的工作；未实现功能仍暂缓。
- 权限规则：用户明确保存的长期 allow/deny 规则按等价语义迁移并遵守目标冲突规则；不支持项明确报告，不通过放宽权限近似转换；历史单次审批不变成目标授权。
- OAuth 登录态：通过各账户所有者的一次性 fixture 验证兼容登录态的导入与正常恢复，目标已有状态不被覆盖，不兼容项明确报告且来源保留；普通任务结果不输出凭据内容。
- 数据完整性：源主库及伴生文件不被迁移器改写；复制附件的内容摘要一致；任务报告不输出凭据或会话正文；畸形 schema、越界路径和符号链接不能越过来源或目标边界。
- 客户端路径：真实 CLI 命令 → 插件 → 所有者 → 原生库 → 历史查看/导出 → 新用户输入 → 捕获模型请求。模型与工具使用本地可观测 fixture，断言历史导入本身不调用模型、不重放旧工具；配置应用引起的正常业务执行按各功能现有流程验证，不以整个宿主零执行作为迁移要求。
- 大小边界：长 Session、单条大消息、超限附件、超过桥接帧的数据必须按已确认分块合同成功，或在发布目标前明确拒绝；不截断后报成功。

优先扩展现有跨 crate 与客户端流程测试，只为无法稳定在流程中触发的数据迁移故障保留专门测试。实现后按实际改动运行相关测试；新增 crate/依赖/装配时按仓库规则运行 `xtask graph/check`，涉及命名服务时更新生成类型，合并前运行规定检查。仅修改文档提议时运行文档检查，不运行实现测试。

## 5. 首版退出条件

给定一个受支持的旧 home，手动 CLI 命令对确认范围内的实体返回可核对结果；失败可重试且不重复导入、不覆盖目标、不破坏来源。用户能够逐条查看旧库仍保存的会话历史、识别导入出处，并通过普通客户端流程发起新请求，模型沿用旧版有效摘要与未压缩后缀，保留原消息角色与工具配对，不重新采用已回退内容。Provider/模型不可用本身不影响历史导入完成，客户端按普通会话逻辑处理；未支持的历史格式按其合同明确报告，不能用自动采用全部原文代替保留旧版续聊状态。

目标业务功能尚未实现的数据明确报告为暂缓并保留旧版来源，支持功能具备后的差量补导，不以整库已迁移标记封死余项。自动触发、Desktop 交互、其他历史版本兼容与没有所有者映射的实体不混入本次导入完成条件，分别按后续设计处理。

## 6. 目标接收能力的代码依据

下表是规划所用的代码基线，不是交付状态；实施时重新核对目标版本、启用配置与所有者合同。

| 目标功能 | 代码依据与规划影响 |
| --- | --- |
| Session、Timeline 与会话上下文 | `crates/dim-agent-runtime/src/agent.rs`、`crates/dim-agent-types/src/events.rs`、`crates/dim-agent-capabilities/src/history.rs`；已有会话与历史投影，但 raw 输入不能保留导入消息的原生角色，需落实 M1 |
| Provider、MCP、Skills、用户命令规则与 Session 文件 | `crates/dim-app-server/src/provider/legacy.rs`、`mcp/config.rs`、`skills_management.rs`、`permission_rules.rs`、`storage/files.rs`；可复用各所有者的接收功能，部分导入和账户恢复仍需所有者合同 |
| Goal、Web、SessionTitle、Scheduler、Workflow | `runtime/default-plugins.json` 已列出默认插件，`runtime/plugins/` 有对应实现；定时任务和 Workflow 不能统一按未实现暂缓，需核对旧格式映射与目标所有者的公开操作 |
| Hooks、ExternalAgent、Modality、RemoteGateway | 代码基线未发现对应业务实现；[路线图](../../design/roadmap.md)和[插件索引](../../design/plugins/README.md)列出其设计。相关数据按目标功能缺失暂缓，功能具备后补导 |
| 归档与客户端元数据 | [客户端合同](../../design/clients.md#5-this-repository-and-desktop)将归档交给客户端本地状态；需按实际目标客户端核对，不能仅由原生库字段推断。目标不支持归档时，整个已归档会话暂缓 |
| 文件回退 | [客户端范围](../../design/clients.md#32-session-management)将文件回退列为范围外；检查点和备份保留旧版，不为迁移补建该业务功能，仍需正确解释有效上下文的回退边界 |
| 插件临时装载 | `crates/dim-app-server/src/plugin_manager.rs` 的 `enable/disable` 会持久化选择；`crates/dim-agent-runtime/src/scope.rs` 和 rutis 已有受所有权管理的子实例机制。核对宿主接入点，不能把持久化开关当成本次临时装载 |
